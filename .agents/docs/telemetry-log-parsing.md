# Telemetry & Transcript Log Parsing

This document details how `AGY-ContextExt` discovers, reads, and parses session logs to extract token consumption metrics.

## 1. Log Discovery & Locations

Antigravity does not provide a direct IPC API to query active context usage. Instead, the extension reads the active conversation's local transcript on the host file system:

- **Windows**: `%USERPROFILE%\.gemini\antigravity\brain\<conversationId>\.system_generated\logs\transcript.jsonl`
- **macOS / Linux**: `~/.gemini/antigravity/brain/<conversationId>/.system_generated/logs/transcript.jsonl`
- **Fallback**: `%USERPROFILE%\.gemini\antigravity\brain\<conversationId>\transcript.jsonl`

The backend resolves the path cross-platform using `os.homedir()` and `path.join()`.

## 2. Telemetry Schema in `transcript.jsonl`

The transcript file is formatted as JSON Lines (`.jsonl`). Each line corresponds to a conversation turn or action.

Key entry types:
- `USER_INPUT`: Contains user prompts and setting changes.
- `PLANNER_RESPONSE`: Contains the model's response, thinking process, tool calls, and backend-reported token counts.

When a line has `type: "PLANNER_RESPONSE"`, the backend extracts the following token metrics:
- `input_tokens`: Prompt tokens consumed during the current turn.
- `cache_read_tokens`: Tokens retrieved from cache (system prompts, rules, active skills, previous turns).
- `output_tokens`: Tokens generated by the model in this turn.

**Authoritative Total Consumed Context**:
```javascript
const totalUsed = latestInputTokens + latestCacheTokens + latestOutputTokens;
```

## 3. Token Breakdown Heuristics

Because per-category token attribution is not exposed as separate integers by the model endpoint, the backend calculates proportional weights based on character counts:

1. **User Messages**:
   - Extracted from `type === 'USER_INPUT'`.
   - Character length converted to token approximation (`chars / 4`).
2. **Agent Responses**:
   - Extracted from `type === 'PLANNER_RESPONSE'` (`content` + `thinking`).
3. **Tool Calls**:
   - Extracted from `tool_calls` arguments in `PLANNER_RESPONSE` plus tool execution outputs (`type === 'GENERIC'`).
4. **System & Cache**:
   - Computed as the remainder:
     ```javascript
     systemTokens = Math.max(0, totalUsed - (userTokens + agentTokens + toolTokens));
     ```
   - This encompasses system instructions, loaded skills, MCP schemas, and contextual caches.
5. **Free Headroom**:
   ```javascript
   freeTokens = Math.max(0, capacity - totalUsed);
   ```

## 4. Model Limit Detection

The backend inspects user setting changes in the transcript (e.g. `<USER_SETTINGS_CHANGE> ... model from ... to ...`):
- Models containing **`Pro`**: Capacity set to **2,097,152 tokens** (2.0M).
- Models containing **`Flash`** (or default): Capacity set to **1,048,576 tokens** (1.0M).
- The detected model name is sanitized with `/^[a-zA-Z0-9\.\s\(\)-]+$/` to avoid regex leakage from logged code snippets.
